# qgis-server-setup

This repository is a hands-on QGIS workflow focused on preparing vector data and then serving the final result through **QGIS Server** using:

- `WMS` for map images
- `WFS` for vector features

The goal is to publish the final layers through WMS and WFS.

The simplest server setup here uses the official `qgis/qgis-server` Docker image and a local QGIS project file such as `qgis_project.qgz`.

## QGIS Server In Docker

Run QGIS Server and mount your local project directory into the container:

```bash
docker run -d -p 8080:80 -v </your/project/folder>:/io/data qgis/qgis-server
```

Example:

```bash
docker run -d -p 8080:80 -v /Users/yourname/projects/qgis-data:/io/data qgis/qgis-server
```

Your QGIS project file should then be available inside the container at a path like:

```text
/io/data/qgis_project.qgz
```

### Serving WMS

Request WMS capabilities from QGIS Server:

```text
http://localhost:8080/ows/?MAP=/io/data/qgis_project.qgz&SERVICE=WMS&REQUEST=GetCapabilities
```

Opening that URL in the browser should return an XML capabilities document.

#### Use The WMS In QGIS Desktop

In QGIS:

1. Go to `Layer > Add Layer > Add WMS/WMTS Layer`.
2. Create a new connection.
3. Set the URL to:

```text
http://localhost:8080/ows/?MAP=/io/data/qgis_project.qgz
```

4. Connect and load the available layers.

#### Using WMS In Leaflet

You can consume the WMS service directly in a Leaflet app:

```js
const wmsLayer = L.tileLayer.wms(
  'http://localhost:8080/ows/?MAP=/io/data/qgis_project.qgz',
  {
    layers: 'sapporo_clipped_utm,roads_clipped_utm,rails_clipped_utm',
    format: 'image/png',
    transparent: true,
    version: '1.3.0'
  }
).addTo(map);
```

### Serving WFS

To publish WFS from the QGIS project:

1. Open the project in QGIS Desktop.
2. Go to `Project > Properties > QGIS Server`.
3. In `Service Capabilities`, enable service capabilities.
4. In the `WFS / OAPIF` tab, enable publishing for the layers you want.
5. `Publish all` if that matches your use case.

Then request WFS capabilities from QGIS Server:

```text
http://localhost:8080/ows/?MAP=/io/data/qgis_project.qgz&SERVICE=WFS&REQUEST=GetCapabilities
```

#### Using WFS In OpenLayers

Use the WFS capabilities endpoint as the starting point for your OpenLayers integration:

```text
http://localhost:8080/ows/?MAP=/io/data/qgis_project.qgz&SERVICE=WFS&REQUEST=GetCapabilities
```

From there, configure your OpenLayers vector source against the published WFS layers.

### Serve Client Apps Over HTTP

If you are testing Leaflet or OpenLayers in the browser, serve the frontend through HTTP instead of opening files directly from disk. This avoids common browser permission and local file access issues.

For a simple static server:

```bash
python -m http.server 8000
```

Then open:

```text
http://localhost:8000
```

The frontend server does **not** need to use the same port as QGIS Server. A common local setup is:

- QGIS Server on `http://localhost:8080`
- Frontend app on `http://localhost:8000`

## Graphic Models

This repository also includes automated QGIS Processing models in [graphic_models](/Users/armstrongngolo/Desktop/qgis-server-setup/graphic_models). These are useful for repeating common preprocessing steps before publishing data through WMS and WFS.

Current models:

- `export vector to wgs84 utm.model3`
- `clip_vector_to_overlay_extent.model3`
- `vector to raster.model3`
- `euclidean from raster.model3`
- `clip raster to overlay extent.model3`
- `merge raster and clip to extent.model3`

### What Each Model Does

`export vector to wgs84 utm.model3`

- Uses `Reproject layer` (`native:reprojectlayer`).
- Reprojects an input vector layer to a target CRS.
- The saved default in the model is `EPSG:32654` which is `WGS 84 / UTM zone 54N`.
- This is useful before area, distance, buffer, and coordinate calculations because those workflows are more reliable in a projected CRS.

`clip_vector_to_overlay_extent.model3`

- Uses `Clip` (`native:clip`).
- Takes an input vector layer and clips it using an overlay layer.
- This is useful for extracting only the part of a larger dataset that belongs to your study area before publishing it.

`vector to raster.model3`

- Uses `Rasterize (vector to raster)` (`gdal:rasterize`).
- Takes a vector layer, a fixed burn value, an overlay extent, and a resolution, then creates a raster output.
- This is useful when a workflow needs raster inputs instead of vectors, for example distance analysis or raster-based suitability workflows.

`euclidean from raster.model3`

- Runs `Proximity (raster distance)` (`gdal:proximity`) and then `Clip raster by mask layer` (`gdal:cliprasterbymasklayer`).
- In practice, it creates a Euclidean distance raster from an input raster and then clips the result to an overlay area.
- This is useful for distance-to-road, distance-to-rail, distance-to-feature, or similar accessibility analyses.

`clip raster to overlay extent.model3`

- Uses `Clip raster by mask layer` (`gdal:cliprasterbymasklayer`).
- Takes an input raster and clips it to the geometry of an overlay layer.
- This is useful for reducing raster size and limiting analysis or publication to a specific area of interest.

`merge raster and clip to extent.model3`

- Runs `Merge` (`gdal:merge`) and then `Clip raster by mask layer` (`gdal:cliprasterbymasklayer`).
- It first combines multiple raster inputs and then clips the merged result to the overlay layer.
- This is useful when source rasters are tiled and you want a single cleaned output for analysis or for use in a QGIS project.

### How The Models Fit The Repo Goal

These models support a practical workflow:

1. Reproject source vectors into a projected CRS such as UTM.
2. Clip vectors and rasters to the study area.
3. Convert vectors to rasters when a raster workflow is needed.
4. Generate derived rasters such as proximity surfaces.
5. Load the cleaned outputs into a QGIS project.
6. Publish the final layers through QGIS Server as WMS and WFS.

In other words, the `graphic_models` folder is the preprocessing side of the project, and QGIS Server is the publishing side.

## Packaging The Project

After preparing data in QGIS, you may also want to package the project for sharing, handoff, or archiving.

### GeoPackage

`GeoPackage` is a practical option when you want to ship data and project content in a compact, portable format.

Notes:

- Install the `Geopacker` plugin in QGIS.
- If direct installation from QGIS fails, install it from the plugin `.zip` file instead.
- This is useful because it is easy to ship to another user or machine.
- The plugin can also produce a PDF report with metadata.

This is helpful when you want a portable deliverable before or alongside WMS/WFS publishing.

### GeoJSON

`GeoJSON` is useful when you need a lightweight vector export for browser-based mapping or simple data sharing.

Notes:

- Export layers to `GeoJSON` when you want a format that works easily with web clients and quick demos.
- Include metadata when possible so the dataset remains understandable outside the original QGIS project.
- This is especially useful for small tutorial datasets and frontend prototypes.

## Working With CSV Data

QGIS can also work with tabular spatial data stored in CSV files.

To add CSV data:

```text
Layer > Add Layer > Add Delimited Text Layer
```

This is useful when your dataset includes coordinates in fields such as `X`, `Y`, `longitude`, and `latitude`.

### CSV With XYZ Coordinates

If the CSV already contains coordinates:

1. Open `Add Delimited Text Layer`.
2. Select the CSV file.
3. Choose the correct geometry definition using the coordinate fields.
4. Map the `X` and `Y` fields correctly.
5. Set the correct CRS before loading the layer.

This is a common way to bring point-based datasets into QGIS for mapping, analysis, and later publication through WMS or WFS.

## Hands-On QGIS Basics

These steps are useful when preparing data before publishing it through QGIS Server.

### Create An Invalid Vector

To intentionally create an invalid polygon layer for testing:

1. Toggle editing on the layer.
2. Add polygons with self-intersections.

You can also use the vertex tool while editing:

1. Click an existing vertex to make it movable, then click a new location to move it.
2. Click between two existing vertices to add a new vertex, then click the new location to place it.

### Check Geometry Validity

Use:

```text
Vector geometry > Check validity
```

This helps detect invalid geometry and can also reveal topology-related issues.

### Fix Geometry

Use:

```text
Vector geometry > Fix geometry
```

Recommended settings:

- Input layer: the original layer
- Repair method: default

### Buffer

Use:

```text
Vector geometry > Buffer
```

Recommended inputs:

- Input layer: your source layer
- Distance: in meters
- Dissolve: `Yes`

Important: use a projected CRS such as `UTM` when working with distance and area in meters.

### Intersection

Use:

```text
Vector overlay > Intersection
```

Example:

- Input layer: `buildings`
- Overlay layer: `flood buffer`

This is a common way to identify features affected by a hazard zone or service area.

### Field Calculator

Before calculating area or coordinate-based values, make sure the layer is in a projected CRS such as `UTM`.

From the attribute table:

1. Toggle editing mode.
2. Click `Field Calculator`.
3. Create the output field and enter the expression.

Useful fields:

- `area_m2`: use expression `$area`
- `X`: for point layers, use `x($geometry)`
- `Y`: for point layers, use `y($geometry)`

If you need coordinates from polygons, use the centroid instead:

- `X`: `x(centroid($geometry))`
- `Y`: `y(centroid($geometry))`

### Field Calculator: Add Intelligence

You can classify features with a `CASE` expression. Use straight single quotes:

```sql
CASE
WHEN $area > 30 THEN 'high'
WHEN $area > 20 THEN 'medium'
ELSE 'low'
END
```

This is useful for turning geometry-derived values into simple categories before publishing.
